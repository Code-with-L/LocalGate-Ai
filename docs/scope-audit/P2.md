## 7. Contradiction / deviation dispositions

- **D-P2-1 — permission 3 (UI safety data-source swap) not performed.** Permission 2 states mocks stay until the simulator UI lands in P3, and `NEXT.md` §5 forbids Gatehead adapter wiring in P2. The domain-side interlock rules required by permission 3 **do** exist and are tested (`evaluateSafetyReport`, `evaluateGateTransition`, `evaluateSafetyStopWhileClosing`, `HoldToConfirmButton` contract). The one-line swap itself is deferred to P3 with the adapter wiring. **Owner ruling requested.**
- **D-P2-2 — property tests are hand-rolled.** Permission 4 requires property-based tests; no external generator was added. `SeededLcg` plus exhaustive/loop-driven invariants cover the three named properties (no activation while safety obstructed, no credential active outside its window, an audit record for every decision). Adding `fast-check` is an owner option, not taken unilaterally.
- **D-P2-3 — toolchain refresh partially resolved.** Permission 5 was exercised to exhaustion within its "non-breaking, no `--force`" constraint: 18 packages updated, `npm audit fix` is a no-op, 5 findings remain. Every fix requires a semver-major jump.
- **D-P2-4 — enum casing canonicalized.** Domain enums are UPPER-CASE in code (`OperatingMode`, `EventSource`, `OperatorRole`, `OperatorLifecycle`, `CredentialStatus`, `DecisionOutcome`, …); `DOMAIN.md`'s lowercase examples are display casing. `GateType` stays lowercase (`"sliding"`) to mirror the document literally. No semantic value was changed by this normalization.
- **Additive conformance edits inside permission 1** (domain core translation of `DOMAIN.md`): `DetectionSource` now includes `"frigate" | "imported"`; `VisitorCredential` gained `siteId`, `createdAtUtc` (derived from the existing injected `nowMs`), and `activeAttemptsWindowConfigRef`, with a new `site-id-missing` validation kind checked before PIN strength; `GateSessionContext`'s dashboard literal is `"dashboard"`. Fixtures in `credential.test.ts` and `simulator/scenario.ts` were updated accordingly.
- **Normalizations recorded, not re-decided:** `Operator`'s doc-level `is_active` is modeled as `lifecycle: ACTIVE | SUSPENDED` + `isOperatorActive`; `Camera`'s `operator_gate_side` is `gateSide`, `stream_cfg_ref` is `streamConfigRef`, and doc `config_validity` is folded into `DeviceStatus`; `CameraStream.codec_info` is `codecInfo`; `AccessDecision`'s doc `gate_session_id?` is `sessionId`; `DecisionDeniedReason` is a code-side superset of the F-05 enum.

No plan decision (D1–D5) was re-decided without declaration.

## 8. Phase boundary verification

- Everything created falls inside the five numbered permissions of `NEXT.md` §5: domain core, simulator engine, safety interlocks as rules, property tests, toolchain refresh. No sixth permission was invented.
- **Nothing from the P2 forbidden list was exercised:** no Gatehead adapter wiring (`web/src/gatehead/` holds only the contract types), no backend/network/persistence (search evidence in §5), no real camera/ANPR (`"frigate"`/`"onnx"` are provenance literals only), no physical-hardware assumptions.

- The suite, `tsc`, lint, format, and build gates listed in §2 all pass on the current working tree; nothing is claimed that was not run.
